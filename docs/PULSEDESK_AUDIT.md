## Старый клиент: устройство

- Одна Activity на 996 строк («god activity»): UI, сеть, хранение, опросы. Страницы переключаются через `visibility`.
- Нет ViewModel, StateFlow, корутин, Compose, DI.
- Потоки: самодельный `Bg` (пулы на 4 и 32 потока плюс Handler).
- `PulseService`: обычный Service, foreground типа `mediaPlayback`.
- Хранение: SharedPreferences `pulse`, токены лежат открытым текстом.
- Дублирование:
  - разбор списка ПК (`MainActivity.loadPcs`, `PulseService.loadLastPc`);
  - разбор ошибок, 3 копии;
  - канал уведомлений создаётся дважды.
- Мёртвый код: `volumeStep`, `ACTION_STOP` (его никто не отправляет), шаблонные тесты.

## Старый клиент: протокол

- Только **API v0**: открытый HTTP на 8765. TLS, пиннинга и WebSocket нет.
- Поиск ПК: UDP `PULSEPC?` → 8766, запасной вариант — перебор /24 через `GET /api/ping`.
- Сопряжение: `POST /api/pair` с подтверждением в окне на ПК.
- Используемые эндпоинты:
  - `status`, `system/*`, `media/*`, `volume`;
  - `player/*`: state, sessions, cover, tracks, команды;
  - `events`, `programs`, `scenarios`, `windows`;
  - `files/*`: roots, list, download, upload, плюс `history`;
  - `monitors`, `screenshot`, `open_url`, `search`.
- Все экраны работают с реальными данными, демо-данных нет.

## Музыкальный модуль — почему работает без музыки

Источник: `PulseService.kt` и `MainActivity.kt` старого проекта.

| # | Причина | Где | Точечное исправление |
|---|---|---|---|
| 1 | Цикл опроса `/api/player/state` каждые 2 с без выхода; сервис остаётся foreground и при `status="none"` | PulseService:114-155 | После ~30 с без воспроизведения — `stopForeground(REMOVE)`; вернуться только при `playing` |
| 2 | Сервис стартует после **каждого** подключения, даже если ничего не играет | MainActivity:260 | Запускать только при активной медиасессии |
| 3 | `START_STICKY`: система поднимает сервис после убийства, и он снова опрашивает ПК | PulseService:100 | `START_NOT_STICKY` |
| 4 | Уведомление MediaStyle перевыпускается каждые 2 с, даже «Ничего не играет»; висит в шторке и на экране блокировки | PulseService:153, 315 | Обновлять только при изменении; без сессии — убирать |
| 5 | `MediaSession.isActive = true` всегда; публикуется STOPPED с метаданными | PulseService:77, 262-275 | `isActive` только для playing/paused |
| 6 | Без связи опрос продолжается каждые 2 с бесконечно | PulseService:142-152 | Нарастающая пауза, затем остановка |
| 7 | `audioPoll` в Activity не снимается в `onPause`: опрос каждые 1,5 с в фоне, параллельно с сервисом | MainActivity:117, 415 | Снимать в `onPause`/`onDestroy` |
| 8 | Нет `onDestroy`: после поворота старая Activity продолжает опрашивать (утечка) | MainActivity | Привязать опросы к жизненному циклу |
| 9 | Громкостные кнопки телефона перехватываются, даже когда ничего не играет | PulseService:232-247 | Remote-громкость только при `playing` |
| 10 | Обложка грузится синхронно в потоке опроса (до 20 с), в полном размере, при ошибке не повторяется | PulseService:132 | Отдельная загрузка, уменьшенное декодирование |

Корневая причина — **HTTP-опрос вместо событий**. Сервер уже присылает `media` по WebSocket `/api/v1/display` при изменениях, раз в 1 с проверяет и раз в 5 с шлёт при воспроизведении. PulseDeck Panel построен на этом, и в нём проблемы нет.

## Безопасность старого клиента

1. **Токен и файлы идут открытым текстом** (`usesCleartextTraffic=true`, `http://`).
2. **ПК опознаётся только по имени.** Любое устройство в сети, ответившее `{"app":"PulsePC","name":"<то же>"}`, получит токен, а сохранённый IP молча переписывается. Это самое серьёзное.
3. Токены хранятся в SharedPreferences без шифрования.
4. Логов с токенами нет.

## Сервер (Windows) — коротко

Подробно: `PULSEDESK_API_COMPATIBILITY.md`.
- v0 HTTP 8765 и v1 TLS 8767 с одним набором маршрутов (`/api/v1/...`) плюс WebSocket `/api/v1/display` (только v1).
- **Права все или ничего**: любой сопряжённый токен может выключить ПК, читать любые файлы, делать скриншоты. Подтверждения на ПК нет.
- Нет на сервере:
  - терминала;
  - списка процессов и установленных программ;
  - переименования, удаления и создания папок;
  - температур (всегда `null`);
  - нагрузки по ядрам;
  - аптайма (на ПК считается, но не отправляется);
  - shuffle/repeat;
  - выбора устройства вывода;
  - выхода из системы;
  - записи экрана.
- Расхождения документации с кодом:
  - `PULSE_MOBILE_API_V1.md` называет QR «не реализован»;
  - пример `hello` в `PANEL_PROTOCOL.md` без `seek`/`volume`.
